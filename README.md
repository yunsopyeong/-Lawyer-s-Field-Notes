# 윤소평 변호사 법률 AI | Lawyer's Field Notes

**대한민국 법률 블로그 글과 유튜브 대본의 초안을 만드는 AI 콘텐츠 프로젝트입니다.**

법인회생·법인파산·개인회생·개인파산을 중심으로, 독자가 궁금해하는 질문을 쉬운 법률 콘텐츠로 정리합니다. 이 저장소에는 윤소평 변호사의 콘텐츠 작성 기준, 재사용할 프롬프트, 주제별 참고자료, 초안 생성 도구와 자동화 예제가 담겨 있습니다.

처음 방문하셨다면 [블로그 프롬프트](02_prompts/blog/naver-blog-main-prompt.md)와 [유튜브 프롬프트](02_prompts/youtube/youtube-script-main-prompt.md)부터 살펴보세요. 프로그램 설치 없이도 프롬프트와 작성 기준을 활용할 수 있습니다.

## 프로젝트 소개

법률 콘텐츠를 만들 때는 조문을 나열하는 것만으로 부족합니다. 독자가 어떤 상황에 놓여 있는지, 어떤 자료를 먼저 확인해야 하는지, 어디서 오해하기 쉬운지를 함께 설명해야 합니다.

이 프로젝트는 **정보 수집 → 분석 → 결론**의 흐름으로 초안을 작성하고, 사람이 근거와 표현을 검토해 발행하는 작업 방식을 정리합니다. AI는 자료 정리와 초안 작성을 돕고, 구체적인 사건의 법률 판단과 발행 전 검토는 사람이 맡습니다.

주요 활용 대상은 법률 콘텐츠를 만드는 변호사와 실무자, 법률 블로그·유튜브 운영자입니다. 대표이사·사업주·개인 채무자가 이해하기 쉬운 설명을 만드는 데 중점을 둡니다.

주요 주제는 법인회생·기업회생, 법인파산·기업파산, 간이회생·일반회생, 개인회생·개인파산입니다. 운영 기준은 민사·형사·가사·상속·성년후견 콘텐츠에도 적용할 수 있도록 구성되어 있습니다.

| 구분 | 활용 내용 | 시작할 자료 |
| --- | --- | --- |
| 네이버 블로그 프롬프트 | 제목, 도입부, 본문, FAQ, 내부링크 문구, 해시태그를 요청하는 작성 기준 | [블로그 프롬프트](02_prompts/blog/naver-blog-main-prompt.md) |
| 유튜브 대본 프롬프트 | 제목, 썸네일 문구, 오프닝, 대본, 설명란, 쇼츠 분리 포인트를 요청하는 작성 기준 | [유튜브 프롬프트](02_prompts/youtube/youtube-script-main-prompt.md) |
| 공통 작성 템플릿 | 정보 수집·분석·결론을 일관된 형식으로 정리 | [작성 템플릿](03_templates/legal-content/info-analysis-conclusion-template.md) |
| 주제별 자료 | 회생·파산의 핵심 질문과 참고자료 정리 | [주제 맵](project-topic-map.md), [주제별 문서](04_topics/) |
| 문체·품질 기준 | 상담형 말투, 과장 표현 점검, 발행 전 검토 | [문체 기준](01_brand/messaging/tone-and-style.md), [최종 검수표](06_operations/quality-control/final-review-checklist.md) |

| API 연동 예제 | 입력 주제를 AI에 전달해 블로그 글·유튜브 대본·썸네일 문구를 파일로 저장 | [main.py](main.py), [생성 모듈](utils/generator.py) |

프롬프트에 적힌 결과물은 사용하는 AI 도구에 요청하는 출력 형식입니다. 자료와 작성 조건을 함께 전달하고, 생성 결과를 검수해 활용합니다.

템플릿 생성 도구는 AI API 호출 없이 정해진 형식의 초안 틀을 만듭니다. API 연동과 외부 게시 자동화 코드는 실행 환경에 맞는 설정과 별도 검증이 필요한 예제입니다. 웹 서비스 공개, 썸네일 이미지 생성, 최신 법령 자동 업데이트는 추가 구현·검증이 필요한 확장 항목입니다.

## 빠른 시작

### 1. 설치 없이 프롬프트 활용하기

1. [운영 정체성](operating-identity.md)과 [문체 기준](01_brand/messaging/tone-and-style.md)을 읽습니다.
2. 블로그 또는 유튜브 프롬프트를 선택합니다.
3. 주제, 독자, 핵심 질문, 확인한 법령·판례·공식자료를 입력 템플릿에 채웁니다.
4. 사용하는 AI 도구에 작성 기준, 프롬프트, 입력 자료를 함께 전달합니다.
5. 결과를 [최종 검수표](06_operations/quality-control/final-review-checklist.md)로 점검하고 편집합니다.

예를 들어 다음과 같이 요청할 수 있습니다.

```text
주제: 법인파산 신청 전 대표이사가 준비할 자료
매체: 네이버 블로그
예상 독자: 폐업과 법인파산의 차이가 궁금한 대표이사
핵심 질문: 신청 전에 어떤 서류부터 정리해야 하나요?
주 키워드: 법인파산 준비서류
반드시 반영할 내용: 회사 채무와 대표이사 개인보증의 구별,
                    자산·채무 목록, 회계자료와 통장 거래내역
참고자료: 직접 확인한 법령·판례·공식자료의 내용과 출처, 확인일
기존 콘텐츠: 관련 글·영상의 제목, 핵심 질문, URL

함께 제공한 운영 기준과 블로그 프롬프트에 따라 초안을 작성해 주세요.
정보 수집 → 분석 → 결론 순서를 유지하고 FAQ와 내부링크 문구를 포함해 주세요.
기존 콘텐츠와 같은 질문을 반복하지 않도록 이번 글의 범위를 좁혀 주세요.
확인하지 못한 조문·판례·통계는 만들어 넣지 말고 '확인 필요'로 표시해 주세요.
```

유튜브 대본이 필요하면 매체를 바꾸고 영상 길이와 예상 시청자를 지정합니다. 고정댓글·메타설명 등 필요한 항목은 추가로 요청할 수 있습니다.

### 2. API 없이 초안 틀 생성하기

저장소를 내려받은 뒤, 저장소 루트에서 다음 명령을 실행합니다. 아래 도구는 Python 표준 라이브러리만 사용하며 API 키가 필요하지 않습니다.

```sh
git clone https://github.com/yunsopyeong/-Lawyer-s-Field-Notes.git
cd -- -Lawyer-s-Field-Notes

python tools/generate_corporate_insolvency_draft.py "법인파산 준비서류" --media blog --output outputs/drafts/corporate-bankruptcy-blog.md
```

`--media`에는 `blog`, `youtube`, `premium`을 지정할 수 있습니다. `--audience`로 독자 유형을 바꿀 수 있고, `--output`을 생략하면 화면에 결과를 표시합니다.

생성 파일에는 검토할 사실관계와 FAQ 질문 등이 담긴 초안 틀이 들어갑니다. 최신 근거와 구체적인 설명을 보완한 뒤 발행용 원고로 편집합니다.

## 콘텐츠 작성 원칙

| 단계 | 확인할 내용 |
| --- | --- |
| 정보 수집 | 독자 유형, 핵심 사실관계, 검색 의도, 필요한 자료, 이번 콘텐츠의 범위 |
| 분석 | 대한민국 법령·판례·공식자료, 관련 법원 실무기준, 요건과 예외, 자주 하는 오해 |
| 결론 | 확인할 서류와 사실관계, 독자가 이해해야 할 판단 기준, 다음 행동 |

법률용어에는 쉬운 설명을 붙이고, 확인되지 않은 정보는 표시합니다. 법령의 시행일, 판례의 사건번호와 취지, 실무준칙의 적용 범위, 통계의 출처와 기준일은 발행 전에 원문으로 확인합니다. 저장소에 있는 요약자료도 최신성 확인이 필요합니다.

검색 의도에 맞는 제목·소제목·FAQ를 설계하고, 기존 글·영상과 핵심 질문이 겹치면 주제 범위를 조정합니다. SEO·GEO·CTR을 고려한 구성은 콘텐츠 설계 목표이며 검색 순위나 조회수를 보장하지 않습니다.

공개 저장소와 AI 입력에는 실명·연락처·사건 식별정보·계정 비밀정보를 포함하지 않습니다. 사례는 익명화하거나 가상 사례로 구성합니다.

## 개발자용 API 연동 예제

`main.py`는 `data/input.txt`를 읽고, `prompts/`의 세 프롬프트를 이용해 콘텐츠 생성을 요청합니다. 실행 전 [utils/generator.py](utils/generator.py)의 모델 식별자와 요청 옵션을 사용 가능한 API 설정에 맞게 확인해야 합니다. 실제 API 호출에는 별도 인증과 비용이 발생할 수 있습니다.

저장소 루트에서 의존성을 설치합니다.

```sh
python -m pip install -r requirements.txt
```

로컬 `.env` 파일에는 콘텐츠 생성에 필요한 키를 설정합니다.

```dotenv
OPENAI_API_KEY=your_openai_api_key
```

`.env`와 실제 API 키는 GitHub에 올리지 않습니다. `data/input.txt`에 익명화한 주제를 입력한 뒤 실행합니다.

```sh
python main.py
```

생성에 성공하면 다음 경로에 결과를 저장합니다. 같은 경로에 파일이 있으면 덮어쓰므로 기존 결과를 보관하려면 먼저 별도로 저장합니다.

| 결과물 | 저장 경로 |
| --- | --- |
| 블로그 글 | `outputs/blog/blog_post.txt` |
| 유튜브 대본 | `outputs/youtube/youtube_script.txt` |
| 썸네일 문구 | `outputs/thumbnail/thumbnail.txt` |

[utils/blog_uploader.py](utils/blog_uploader.py)는 별도의 네이버 게시 자동화 예제입니다. 실행하면 실제 발행을 시도하므로 원고 검수, 게시 권한, 로그인 방식과 화면 요소를 확인한 뒤 사용합니다. 콘텐츠 생성만 할 때는 네이버 계정 정보를 설정할 필요가 없습니다.

## 개선 제안과 참여

이 자료가 도움이 되셨다면 저장소를 Star로 표시하거나 링크를 공유해 주세요. 오류와 개선 제안은 [Issues](https://github.com/yunsopyeong/-Lawyer-s-Field-Notes/issues)에 남길 수 있습니다.

법률정보 수정 제안에는 원문 출처, 확인일, 수정할 파일 경로를 적어 주세요. 프롬프트 개선 제안에는 입력 조건과 원하는 결과를, 실행 오류에는 재현 방법을 함께 남겨 주시면 검토에 도움이 됩니다.

변경 작업은 `draft/...` 또는 `hotfix/...` 브랜치에서 진행하고, 한 PR에는 한 주제를 담습니다. 관련 자료·링크와 검수 결과를 확인한 뒤 `main`에 병합합니다. 자세한 업무 기준은 [Codex 작업 목록](06_operations/codex/codex-task-list.md)을 참고하세요.
